# Principe — Blue/green sur Elastic Beanstalk, en schémas
@slide title Blue/green sur Elastic Beanstalk
Principe en schémas · Domaine 1
Le swap de CNAME, et pourquoi la base doit vivre ailleurs
@end
L: Le {blue/green} sur {Elastic Beanstalk}. Deux pièges dans un seul schéma, Rémy ?
R: Oui. Un : ce n'est pas une politique de déploiement, c'est une action. Deux : si la base de données vit dans l'environnement, elle disparaît avec lui.

L: On part de l'environnement bleu, en production.

@show green g1

@show rds d1 d2

@hide u1
@show u2
@focus users u2 green g1
@flow u2
R: Quand tout est prêt : {Swap Environment CNAMEs}. Les {URL} sont échangées, les utilisateurs arrivent sur le vert. Et le {rollback} est instantané : on refait le {swap}.

@show del
@focus del rdsin

@slide cards Elastic Beanstalk : à retenir

Blue/green :: **Pas une politique** : 2 environnements + SwapEnvironmentCNAMEs

Tâches de fond :: Worker environment + cron.yaml (SQS)

L: On résume ?
R: Cinq politiques de déploiement, le {blue/green} à part avec le {swap} de {CNAME}, la base hors de l'environnement. Et les {ebextensions} pour personnaliser.
